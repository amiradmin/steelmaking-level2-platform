# Dashboard incident — 2026-11-16

All times below are Tehran (UTC+03:30). Raw evidence uses UTC.

## Confirmed cause and sequence

The overview recent-heats query aggregated process_samples across all heats before LIMIT 6. At capture, six client SELECTs had run for 8–11 minutes with no blocking PIDs, waiting on data or temporary-file I/O. API Docker health was unhealthy; PostgreSQL and gateway health were healthy.

Logs show overview 504 at 14:05:11, auth/me still 200 at 14:05:20, then Reports 504 at 14:06:20. At 14:20:14 auth/me failed with a gateway connection timeout. Direct authenticated permissions and in-container health probes also timed out before recovery. This supports a shared API outage driven by the runaway overview reads, rather than evidence of an expired session or an independent RBAC failure. The exact application scheduling mechanism was not profiled.

Six identified overview SELECTs were cancelled with pg_cancel_backend, guarded by current database, client backend, active state, query signature, and age. No writes were cancelled. Permissions and health immediately recovered. Existing Reports then returned 24 heats in 2.769 seconds while permissions and health remained available.

## Deployed change

Only backend/level2_api/api/overview_live.py changed on the server. Select the six most recently created heats first, then calculate each heat's peak EAF temperature with a lateral aggregate filtered to its temperature tag. Preserve NULL results and all original calculations. A repeatable-read, read-only comparison against the original aggregate restricted to those same six heats returned zero differing rows.

Plain EXPLAIN was used; EXPLAIN ANALYZE was not used. The deployed Reports handler already limits heat selection first. Valid heat_id indexes exist on all three weekly chunks, and its plan uses them. Reports remains unchanged (SHA-256 6959d523ba9f66b41e13bf2ca1531871a500a81231026f6abb31d325fc7117a4).

The API image was rebuilt specifically for the new overview change and only level2-api recreated. Other services and existing server hotfixes were preserved. No retention, compression, index, or other database schema changes were made.
