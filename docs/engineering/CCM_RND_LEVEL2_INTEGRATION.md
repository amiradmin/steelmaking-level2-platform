# CCM R&D PLC — PLC-native simulation and read-only Level-2 integration

## Architecture

The synthetic CCM process is generated by the Siemens S7-SCL application in
`plc/s7_400h_ccm_rnd/`:

- OB1 calls FB300 (instance DB301) and FB310 (instance DB311).
- FB300 is the sole writer of process DB300.
- FB310 is the sole writer of diagnostics DB310.
- The Ubuntu Level-2 S7 gateway reads DB300/DB310 only.
- The ingestor stores CCM samples with
  `attributes.source_kind = "RND_PLC_TEST"`.

The gateway remains read-only. EAF and LF remain on their existing simulators.
The normal Compose startup is unchanged; the physical CCM integration is
opt-in through `docker-compose.ccm-rnd.yml`.

## Important: no competing writer

The previous Ubuntu/Snap7 writer architecture is superseded for physical
operation by the PLC-native SCL source. The Python writer remains useful for
offline dry-run packing tests and read-only DB backup, but
`--enable-plc-writes` now fails closed. Do not re-enable it or run a second
writer against DB300/DB310.

## Hard preconditions

1. Resolve the CPU STOP/EXTF and CP INTF indications. These faults were
   reported during commissioning and are not yet diagnosed.
2. Obtain a complete STEP 7 station/program backup and a recovery plan.
3. Compile the SCL source offline using a Siemens engineering version verified
   for the actual CPU order number and firmware.
4. Inspect DB300 and DB310 after compilation. Verify exact sizes and offsets
   against `plc/s7_400h_ccm_rnd/DB_LAYOUT.md`.
5. Verify DB301 and DB311 are the intended instance DBs for FB300 and FB310.
6. Download only after qualified engineering review and explicit commissioning
   approval.
7. Read back DB300 and DB310 with Snap7 and verify the values before starting
   the physical CCM Level-2 gateway.
8. Keep a separately reviewed full physical address map. The repository's
   `backend/plc_simulators/s7_address_map.json` is simulation-only and must
   never be used as the physical CCM map.

Snap7 cannot compile SCL or create/download native Siemens logic blocks.

## Connection settings

The tested endpoint is currently:

```dotenv
CCM_RND_PLC_HOST=192.168.1.10
CCM_RND_PLC_PORT=102
CCM_RND_PLC_RACK=0
CCM_RND_PLC_SLOT=3
CCM_RND_S7_ADDRESS_MAP_FILE=/absolute/path/to/verified-full-s7-map.json
```

These values establish network reachability only. Confirm the CP interface,
rack/slot routing and hardware configuration with the PLC engineer before
using them for the physical gateway.

## Offline Python dry-run

The Ubuntu writer's default mode remains a no-PLC dry-run:

```bash
docker compose -f docker-compose.yml -f docker-compose.ccm-rnd-writer.yml \
  --profile ccm-rnd-writer run --rm ccm-rnd-s7-writer \
  python ccm_s7_writer.py --once
```

This validates the legacy Python process model and byte packing only. It does
not compile, download or run the PLC-native SCL application.

The writer's `--backup-only` option performs read-only DB reads and stores the
raw DB300/DB310 byte ranges if those blocks exist. It is not a complete PLC
station backup. The physical write option is disabled.

## Read-only verification after commissioning

After the SCL application has been compiled and downloaded through the
approved Siemens engineering process, verify the two DBs:

```bash
cd ~/Documents/Presentation/steelmaking-level2-platform

docker compose \
  -f docker-compose.yml \
  -f docker-compose.ccm-rnd-writer.yml \
  --profile ccm-rnd-writer run --rm \
  --entrypoint python ccm-rnd-s7-writer -c '
import snap7
client = snap7.Client()
try:
    client.connect("192.168.1.10", 0, 3, tcp_port=102)
    for db, size in ((300, 48), (310, 12)):
        data = client.db_read(db, 0, size)
        print("DB", db, "length", len(data), "hex", data.hex(" "))
finally:
    if client.get_connected():
        client.disconnect()
'
```

This is a read-only check. Compare the bytes against the verified compiled
layout and decode the REAL/INT/DINT fields before enabling the gateway.

## Level-2 activation

Only after the physical map is independently reviewed:

1. Configure the CCM gateway client with the verified host, rack, slot and
   physical address map.
2. Preserve the read-only gateway boundary.
3. Keep EAF and LF on their simulator endpoints.
4. Validate the merged Compose configuration.
5. Start only the opt-in CCM R&D integration overlay.
6. Confirm all 25 logical CCM tags have fresh GOOD-quality historian samples
   with `source_kind=RND_PLC_TEST`.
7. Confirm the System Map R&D readiness gate remains false until all required
   tags meet the provenance and freshness conditions.

## Rollback

Stop the opt-in integration overlay and return to the base Compose
configuration. Do not erase or reset the PLC as a rollback mechanism. If the
PLC application must be reverted, use the verified STEP 7 backup and the
approved engineering procedure.
